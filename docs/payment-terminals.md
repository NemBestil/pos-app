# Payment-terminal monitoring

UDP on port 8000 supplies terminal IDs and addresses. For each configured terminal with credentials, a tablet reports it available when **either a local UDP broadcast or a successful TCP check occurred within the last five minutes**. Every broadcast renews availability, including repeated broadcasts from an unchanged endpoint. Cached discovery or server `lastSeenAt` values alone never establish current local access.

`PaymentTerminalReachability.java` owns the shared five-minute window, monotonic observation times, expiry timers, TCP scheduling and available endpoints. `ForwarderService.java` owns discovery, Wi-Fi-bound calls and POS socket reporting. It retains both wall-clock and monotonic receipt times for local UDP observations so applying configuration can recognize an earlier broadcast without extending its original expiry.

Each tablet opens and closes TCP port **8080** once per minute with a **10-second connect timeout**. TCP success is sufficient for availability; signed DeviceInformation verification is not a prerequisite for monitoring. TCP and forwarded terminal operations use the current Wi-Fi network. The newer of local discovery and server address observations supplies the target.

A failed TCP check allows three retries after the first attempt, with at least 10 seconds from completion of one attempt to the next. Failures, including exhausted retries, never override recent UDP/TCP evidence. Availability expires five minutes after the most recent successful observation, with an immediate device report, even during a pending check. Offline monitoring continues every minute and either a broadcast or TCP success can restore access. Wi-Fi/endpoint changes clear old availability; in-flight results from replaced states are discarded. A fresh broadcast for the new endpoint immediately establishes its availability.

Monotonic per-terminal deadlines launch independent workers; printer availability never gates terminal checks. A separate timer sends `devices.snapshot` every minute, including an empty available list. Observations and expiry report immediately without waiting for printer scans. `lastSeenAt` is the wall-clock time of the most recent local UDP/TCP observation; wall-clock changes do not extend the five-minute window.

Registration/snapshots report `terminalCandidates` separately from available `devices`. Only signed GET `/api/v2/DeviceInformation` setup requests may use unavailable candidates, preserving automatic authorization and manual credential edits. Payments and other operations require available endpoints. UDP/TCP reachability is not payment authorization: credentials, signed responses and the POS checkout status/busy check remain enforced by the server. The Capacitor discovery plugin exposes UDP observations only.

The existing POS identity-probe socket topics, configuration `canVerifyIdentity`/`lastSeenAt`, and legacy signed configuration probe remain supported by the server for previously released APKs. Current monitoring does not request identity probes. Android socket protocols 3/4 and forwarded operation payloads are unchanged. This fix requires a newly built and installed APK; a web-only update cannot replace native monitoring. No new POS API or migration is required for this fix.

Physical validation should cover UDP-only access despite failed TCP, TCP-only access without UDP, repeated unchanged broadcasts, exhausted retries within the five-minute window, exact expiry and recovery, configuration reapplication without refreshing stale evidence, clock changes, Wi-Fi/IP changes during I/O, and adding/authorizing a terminal. Compile Java through the existing source-linking script with JDK 21.
