# USB access after reboot or printer reconnection

The app registers `MainActivity` for `USB_DEVICE_ATTACHED` using `resources/android/xml/usb_device_filter.xml`. `scripts/android-patch.sh` installs the manifest entry and links the XML into the generated Android project. The filter deliberately matches all USB devices because printer ports can use vendor-specific interfaces rather than USB printer class 7. Android may offer the app when other USB peripherals are attached; access still requires a per-device user grant, and the forwarder prints only to configured printers.

In Android's USB permission/open-app dialog, select **Always use** for NemBestil POS and confirm. Android stores the default handler and grants access again when that device is enumerated after reconnecting or rebooting. `UsbPrinterPlugin.handleOnNewIntent()` receives both initial and `singleTask` attachment launches through Capacitor, checks `UsbManager.hasPermission()`, restarts forwarding only when credentials are already configured, and refreshes device availability after the grant. The earlier attachment broadcast alone is insufficient because it can precede the permission grant.

When upgrading from a one-time grant, reconnect or power-cycle the printer after installing the new APK, then approve once with **Always use**. Merely approving without that option remains temporary. There is no public Android permission for permanent access to every USB device; resetting app defaults, changing devices, or manufacturer firmware behavior can require another approval. Verify on the customer's Android POS: approve with **Always use**, power-cycle the printer, reboot with it connected, and repeat with the app closed and running. Also verify denial and two printers of the same model; printer identity matching must stay unambiguous.

Receipt delivery in app 1.4.2 reads queued ESC/POS completion status through bulk IN on the same claimed interface as bulk OUT. From app 1.4.3, missing bulk IN still prints and uses bounded timed recovery instead of failing; queued status is advisory. This does not alter permission or reconnect handling. See [receipt completion and cutter ownership](receipt-printing.md).

## Platform reference

[Android USB host documentation](https://developer.android.com/develop/connectivity/usb/host) describes attachment filters and temporary device grants. Android's [USB permission dialog](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android16-release/packages/SystemUI/src/com/android/systemui/usb/UsbPermissionActivity.java) offers **Always use** when the app has a matching filter; its [USB handler resolution](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/services/usb/java/com/android/server/usb/UsbProfileGroupSettingsManager.java) grants access to the saved default before launching it. Manufacturer firmware may differ.
