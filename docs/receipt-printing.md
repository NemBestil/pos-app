# Direct receipt printing

App 1.4.1 uses Android socket protocol 4. `print.job` carries `printerLanguage` (`esc-pos`, `star-prnt`, `star-line`), `feedLines`, and an ordered `documents` array with base64 body bytes and `cut` (`full`, `partial`, or null). The hosted POS removes physical cuts and model cutter feed before delivery while keeping binary image/QR/barcode data intact. This APK consumes only the protocol 4 contract. The hosted server also supports older protocol 3 APKs by sending those receivers their original root raw payload with CUT commands; it never sends those legacy cuts to this APK. Publish the signed target APK before deploying the matching POS minimum/target requirements.

`resources/android/ForwarderService.java` assigns each printer a single-thread executor. One printer's jobs cannot overlap, even across WebSocket reconnections; distinct printers have independent executors. Delivery job IDs are remembered while queued/running and for five minutes afterward to ignore duplicate envelopes. Result ACK retries never print the document again. Acceptance must be acknowledged before writing to hardware; final success follows the entire native transfer, cuts and recovery pauses.

`resources/android/PrinterJobWriter.java` owns paper boundaries for LAN, Bluetooth and USB. On the same connection it writes the complete document, flushes, resets line spacing, feeds the model's cutter distance, sends one full/partial CUT, flushes and waits 1,000 ms from app 1.4.2 (500 ms in 1.4.1). Only afterward can the next document/copy/job start or the service report success/close the connection. It never initializes or clears the print buffer between the body and its cut. Every receipt frame cuts; null-cut cash-drawer pulses do not feed/cut. Multiple pages/copies within one server job are separate frames. The hosted POS adds no second recovery pause for this APK; it supplies a server-owned pause only for older legacy receivers. Transport success is not a physical cutter sensor acknowledgement.

Bluetooth transfers use 2,048-byte chunks, flushing and pacing each chunk by 20 ms to avoid unpaced large graphics writes. The cutter is a separate write after the final body chunk. USB wraps bulk transfers in an OutputStream and handles partial writes for both bodies and cuts. USB identity, permission and reconnect behavior is unchanged; see [USB access](usb-access.md). Interrupted or failed writes must report failure, never success or advance into a later frame.

From app 1.4.3, ESC/POS receipts use advisory queued status (`GS r 1`) on the same Bluetooth, LAN or USB connection. Do not probe/block before paper data: disable unsolicited ASB if a return channel exists, then send the complete body. Body and cutter status checks share one deadline of 14 seconds after the body flush, reserving 1 second for cutter recovery; total recovery is at most 15 seconds per receipt, excluding blocked transport writes. A body reply permits an immediate CUT and a cutter reply permits the normal 1-second pause. If a reply is absent or status reading fails, finish the bounded wait, send CUT and continue normally without marking a status failure. After any timed-out query, use timed recovery for remaining documents on that connection so a late reply cannot acknowledge another page. Missing USB bulk IN uses the same timed recovery and still prints. Actual output-write failures, interruption and explicit paper-out status remain errors. Cash-drawer pulses skip these queries. Star command languages retain transport completion plus the 1-second pause. App 1.4.2 required status and failed after 30 seconds; this strict behavior was replaced at the user's request.

Android `flush()` only confirms transfer to the transport, while [queued ESC/POS status](https://download4.epson.biz/sec_pubs/pos/reference_en/escpos/gs_lr.html) is processed after the preceding print operations; realtime `DLE EOT` cannot provide this boundary. Discard complete four-byte ASB/realtime replies rather than treating them as completion. USB selects bulk IN and OUT endpoints on the same claimed interface and buffers bounded 10 ms bulk IN polls when available. LAN consumes replies during the job instead of draining them after shutdown. The hosted server completion deadline must include its original 45-second transfer allowance plus 15 seconds per cut-bearing native document/copy; drawer-only and legacy jobs keep the original deadline. Missing status completion is a tolerated delivery mode, not evidence that paper has physically finished.

Source files belong in `resources/android/`; `scripts/android-patch.sh` links the writer into the generated Android package. Validate by generating the shell, syncing Capacitor, applying the patch, and compiling/assembling with JDK 21. Focused stream checks must preserve binary image data and assert body 1 → queued completion → cut → queued completion → 1,000 ms → body 2 → cut, full/partial Star and ESC/POS commands, drawer exclusion, optional/missing/failed status reads, a shared 15-second recovery cap, and interruption. Physically test text and graphical jobs/copies on the customer's XPrinter Bluetooth device; stream/build checks cannot verify its firmware or cutter mechanics.
