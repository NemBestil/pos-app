# Android launcher

`app/app.vue` owns the launcher, installation wizard, saved-installation management and launch/version gate. Shell text is English.

At widths of at least 600 CSS pixels, the home screen and wizard use a vertically centered grid: branding occupies the left 2/5 and controls the right 3/5. Phones stack these areas. Logo heights, padding and gaps scale with viewport height to keep the ordinary home screen usable on small tablets without vertical scrolling. Do not reserve a fixed-height customer-logo panel. Long installation lists, wizard details, system notices and the onscreen keyboard may need scrolling; keep content accessible rather than clipping it.

`app/components/CustomerLogo.vue` is shared by branding and the saved list. Missing/empty URLs render no image, and loading images stay hidden until success. A load error removes the image; a URL change resets its loading/error state. No broken-image icon or empty customer-logo panel should remain. Apply the customer's background color directly to loaded list images so white logos remain visible without reserving an empty panel for failed images.

## Connection and launch

The selected installation is checked automatically on startup, selection, returning to the home screen, app visibility restoration and browser online events. `checkInstallationConnection` coalesces concurrent requests for the same ID and tracks status by ID, so an old response cannot change another selection's status. Successful checks refresh and persist organization/branding metadata; failed checks retain the saved installation and show device/network troubleshooting with **Try again**. Requests use `CapacitorHttp`, request uncached metadata, and set five-second connect/read timeouts.

The home screen displays the selected installation URL and checking/connected/unavailable status. Unavailable installations show Wi-Fi/LAN, Chrome/browser internet-check and device-restart guidance. **Open POS** is enabled only after a successful check and startup permission initialization. Opening performs another fresh check and retains the existing installation-specific app-version gate. Automatic checks never prompt for an update or navigate. Network failures during wizard verification include the attempted URL, ID check and the same troubleshooting advice.

After **Manage installations → Add installation → Verify → Add installation**, return to the home screen with the saved installation selected, without opening the POS automatically. The original first-installation **Open POS** flow still saves and launches through the version gate. The management list also displays each installation's full URL.

## Saved-domain migration

`app/utils/installation-url.ts` derives all installation origins from their IDs as `https://<id>.nbpos.eu`, lowercasing the hostname. `NGROK` remains the explicit `https://nbpos3.ngrok.dev` development alias. There is no legacy-domain discovery fallback. Keep the existing localStorage keys so APK updates retain installation IDs, default selection, organization data and history. On launcher startup, replace saved base URLs with these canonical origins and migrate full/square logo URLs from exact legacy installation hosts, preserving asset paths/query strings. Persist before any network check, including while offline. Apply the same logo migration to refreshed API metadata.

`resources/android/ForwarderService.java` also normalizes exact `*.pos3.nemkasse.com` installation origins to HTTPS `*.nbpos.eu` before explicit starts, sticky restarts and configured-origin reads. Persist the migrated origin while retaining its token and forwarder ID. This covers background restarts after an APK update even before the launcher opens. Do not redirect arbitrary hostnames or change payment-result outbox origins, signed history, or the external native `whoami.nemkasse.com` contract.

`capacitor.config.ts` allows only `*.nbpos.eu` and the explicit NGROK host. Remove both the old installation wildcard and the broader `*.nemkasse.com` wildcard so bridge injection cannot still permit old installation pages. Regenerate the packaged shell and run Capacitor sync when building the updated APK; source edits alone do not change installed apps.

## Validation

Generate the shell, sync Capacitor, apply Android patches and compile release Java with JDK 21. Review generated navigation hosts and exercise offline/online lookup, selection races, legacy localStorage/native preferences, missing/error logos and add-installation return behavior. Browser/preview verification and new test files are opt-in repository workflows. Device acceptance should cover small portrait/landscape tablets and phones, failed DNS/HTTP/timeout responses, retry/reconnection and the unchanged app-version gate.
